# 竞品情报分析

系统理解竞争格局，找到可差异化的缝隙。不是列出所有竞品，而是回答：他们在做什么？哪里做得不好？我们能不同在哪里？

## 铁律

1. **不编造竞品数据。** 功能、定价、用户数找不到就写"未核实"。
2. **事实与判断分开。** 功能对比是事实，"他们做得不好"是判断，要分开写。
3. **竞品多不等于不能做。** 关键看有没有缝隙，不是看有没有人。
4. **不抄竞品。** 分析是为了差异化，不是为了复制。
5. **定期更新。** 竞品信息会过时，记录核验日期。

## 分析框架

### 竞品识别
- **直接竞品**：解决同一问题、同一目标用户
- **间接替代**：不同方案解决同一问题（如 Excel 替代专门工具）
- **潜在进入者**：大厂、开源项目、相邻产品可能扩展
- 列 3-5 个核心竞品，不要贪多

### 功能对比矩阵
| 功能 | 我们 | 竞品A | 竞品B | 竞品C |
|---|---|---|---|---|

- 标注每个功能的重要性（核心/加分/无关）
- 找竞品普遍缺失但用户需要的功能 = 差异化机会

### 定价分析
- 定价模式：订阅/买断/按用量/免费增值
- 价格层级和各层级包含什么
- 有没有免费试用/免费层
- 用户抱怨定价的评论 = 定价策略机会

### 用户反馈分析
- 评价网站评分和常见抱怨（G2、Capterra、Product Hunt）
- 社区讨论中的不满（Reddit、HN、论坛）
- 支持工单中的高频问题（如果公开可见）
- 用户想要的功能 vs 实际提供的功能

### 定位与消息分析
- 他们怎么描述自己？（tagline、价值主张）
- 目标客户是谁？（中小企业/个人/企业）
- 核心卖点是什么？
- 有没有定位模糊或自相矛盾？

### 分发渠道
- 主要获客渠道（SEO、社区、广告、合作伙伴）
- 内容策略（博客、视频、社交媒体）
- 目录和平台存在（Product Hunt、G2、Capterra）
- 合作和集成生态

## 工作流程

### 1. 确定分析范围
- 分析目的：新产品定位？功能规划？差异化策略？
- 关注维度：功能、定价、用户反馈、渠道、定位？
- 时间范围：当前状态还是历史变化趋势？

### 2. 收集竞品列表
- 从 `indie-product-radar` 或 `product-validation` 的竞品研究开始
- 搜索"best [category] tools"、"[category] software"
- 查看 G2、Capterra、AlternativeTo 的分类列表
- 用户评价中提到的其他产品

### 3. 逐个深度分析
对每个核心竞品：
- 官网和定价页
- 功能列表和更新日志
- 用户评价（至少 3 个来源）
- 社区讨论和提及
- 内容策略和 SEO 表现

### 4. 找差异化机会
- 功能缝隙：用户需要但竞品普遍缺失
- 定价机会：用户对现有定价不满
- 定位缝隙：未被充分服务的细分市场
- 渠道机会：竞品忽视的获客渠道
- 体验问题：竞品普遍存在的 UX 问题

### 5. 输出竞争情报报告
结构化输出，包含：
- 竞品概览和定位对比
- 功能矩阵和差异化机会
- 定价对比和机会
- 用户反馈中的共同痛点
- 可执行的差异化建议

## 持续监控

竞品情报不是一次性工作。建议每月花 30-60 分钟：
- 检查竞品更新日志和公告
- 监控新的用户评价和讨论
- 跟踪定价变化
- 注意新的进入者

## 与其他 Skill 的关系

- `indie-product-radar`：发现机会时做初步竞品扫描
- `product-validation`：验证阶段需要竞品证据
- `seo-opportunity-research`：分析竞品的 SEO 策略
- `product-positioning`：基于竞品分析确定差异化定位
- `content-marketing-engine`：基于竞品内容策略找内容机会
- `indie-product-reach`：推广时参考竞品的渠道策略
