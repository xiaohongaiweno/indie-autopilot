# 转化优化

提升用户转化率。核心问题：用户在哪里流失？为什么流失？如何改进？

## 铁律

1. **数据驱动。** 基于数据发现问题，不是猜测。
2. **假设先行。** 先形成假设，再设计实验。
3. **一次一变。** 每次只改一个变量，才能归因。
4. **统计显著。** 实验结果要统计显著才算有效。
5. **持续迭代。** 转化优化是持续过程，不是一次性工作。

## 转化漏斗

### 典型 SaaS 漏斗
```
访问网站 → 查看定价 → 注册 → 完成 onboarding → 使用核心功能 → 付费 → 续费
```

### 每个阶段的关键指标
- **访问 → 查看定价**：价值主张清晰度
- **查看定价 → 注册**：定价吸引力、注册摩擦
- **注册 → 完成 onboarding**：onboarding 体验
- **完成 onboarding → 使用核心功能**：激活率
- **使用核心功能 → 付费**：付费转化
- **付费 → 续费**：留存率

## 优化框架

### 问题分析
对每个转化点：
- **当前转化率**：多少用户在转化？
- **流失率**：多少用户流失？
- **流失原因**：为什么流失？
- **改进机会**：如何改进？

### 常见转化问题
- **价值主张不清**：用户不理解产品价值
- **注册摩擦**：表单太长、要求太多
- **定价困惑**：方案太多、价格不透明
- **信任缺失**：没有社交证明、没有保障
- **流程断裂**：步骤太多、页面跳转混乱
- **移动端体验差**：移动端转化率低

### 优化策略
- **价值主张优化**：清晰的标题、副标题、CTA
- **注册优化**：减少字段、社交登录、渐进式注册
- **定价优化**：简化方案、突出推荐、透明定价
- **信任建设**：社交证明、安全保障、退款保证
- **流程简化**：减少步骤、清晰指引、进度指示
- **移动端优化**：响应式设计、简化表单、大按钮

## A/B 测试

### 测试流程
1. **发现问题**：数据分析发现转化问题
2. **形成假设**：为什么有这个问题？如何改进？
3. **设计实验**：改什么？怎么改？预期效果？
4. **实施测试**：A/B 测试工具配置
5. **运行测试**：等待统计显著
6. **分析结果**：哪个版本更好？显著吗？
7. **应用结果**：应用获胜版本，记录学习

### 测试工具
- **VWO / Optimizely**：企业级 A/B 测试
- **Google Optimize**：免费 A/B 测试
- **PostHog**：开源 A/B 测试
- **Unbounce / Instapage**：落地页 A/B 测试

### 测试最佳实践
- **明确假设**：我预期 X 会提升 Y，因为 Z
- **一次一变**：只改一个变量
- **足够样本**：等待统计显著（通常 95% 置信度）
- **足够时间**：至少运行 1-2 周
- **记录学习**：无论结果如何，记录学习

## 工作流程

### 1. 漏斗分析
- 绘制完整转化漏斗
- 计算每个阶段的转化率
- 识别转化率最低的阶段
- 分析流失原因

### 2. 问题诊断
对低转化阶段：
- 用户行为数据（点击、滚动、停留时间）
- 用户反馈（调查、访谈、支持工单）
- 竞品对比（竞品如何做的？）
- 最佳实践（行业标准是什么？）

### 3. 形成假设
基于诊断：
- 问题是什么？
- 为什么有这个问题？
- 如何改进？
- 预期效果是什么？

### 4. 设计实验
- 改什么？（标题、CTA、表单、定价）
- 怎么改？（具体变化）
- 如何衡量？（主要指标、次要指标）
- 需要多少样本？（统计功效计算）

### 5. 实施测试
- 配置 A/B 测试工具
- 设置变体
- 测试配置正确性
- 开始测试

### 6. 分析和应用
- 等待统计显著
- 分析结果
- 应用获胜版本
- 记录学习和洞察

- [ ] 进度指示
- [ ] 帮助和支持
- [ ] 快速见效
- [ ] 减少认知负担
