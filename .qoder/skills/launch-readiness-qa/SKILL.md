# 发布前质量检查

确保产品可以安全发布。核心问题：所有功能正常吗？性能可接受吗？安全措施到位吗？用户体验流畅吗？

## 铁律

1. **不跳过关键检查。** 安全和数据完整性检查必须通过。
2. **真实环境测试。** 在类生产环境测试，不只是本地。
3. **用户视角验证。** 从用户角度走完整流程，不只是开发者视角。
4. **有回滚计划。** 发布失败时能快速恢复。
5. **记录所有问题。** 已知问题要记录，不要假装没问题。

## 检查清单

### 功能测试
- [ ] 核心流程可走通（注册、登录、主要功能）
- [ ] 边界情况处理（空值、超长输入、特殊字符）
- [ ] 错误处理（网络错误、服务器错误、用户错误）
- [ ] 数据一致性（创建、读取、更新、删除）
- [ ] 第三方集成（支付、邮件、API）

### 性能测试
- [ ] 页面加载时间 < 3 秒
- [ ] API 响应时间 < 500ms
- [ ] 并发用户支持（至少 10 个并发）
- [ ] 数据库查询优化（无慢查询）
- [ ] 资源使用（内存、CPU、磁盘）

### 安全检查
- [ ] HTTPS 配置正确
- [ ] 认证和授权正常
- [ ] 输入验证到位
- [ ] 敏感数据加密
- [ ] 安全头配置（CSP、HSTS 等）
- [ ] `security-privacy-review` 已完成

### 用户体验
- [ ] 移动端适配
- [ ] 浏览器兼容性（Chrome、Firefox、Safari、Edge）
- [ ] 可访问性（键盘可操作、屏幕阅读器）
- [ ] 错误消息清晰
- [ ] 加载状态和反馈
- [ ] `product-ux-conversion` 流程验证

### 部署准备
- [ ] 环境变量配置
- [ ] 数据库迁移脚本
- [ ] 备份策略
- [ ] 监控和日志
- [ ] 回滚计划
- [ ] `deployment-operations` 准备就绪

### 业务准备
- [ ] 定价和支付流程
- [ ] 隐私政策和条款
- [ ] 联系方式和支持渠道
- [ ] 文档和帮助页面
- [ ] 社交证明（如果有）

## 工作流程

### 1. 准备测试环境
- 克隆生产环境配置
- 导入测试数据
- 配置监控和日志
- 准备测试账号

### 2. 自动化测试
- 运行单元测试
- 运行集成测试
- 运行端到端测试
- 检查代码覆盖率

### 3. 手动测试
- 走完整用户流程
- 测试边界情况
- 测试错误场景
- 测试移动端
- 测试不同浏览器

### 4. 性能测试
- 负载测试（预期流量的 2-3 倍）
- 压力测试（找到极限）
- 持久性测试（长时间运行）
- 优化瓶颈

### 5. 安全审查
- 运行安全扫描
- 手动检查常见漏洞
- 检查依赖漏洞
- 验证认证和授权

### 6. 用户体验验证
- 找 3-5 个目标用户测试
- 观察他们完成核心任务
- 收集反馈
- 修复关键问题

### 7. 最终检查
- 所有 P0 问题已修复
- P1 问题有明确计划
- 回滚计划准备就绪
- 团队准备就绪

## 问题分级

### P0（阻塞发布）
- 核心功能不可用
- 数据丢失或损坏
- 安全漏洞
- 支付失败
- 认证失败

### P1（发布前修复）
- 重要功能有 bug
- 性能问题
- UX 问题
- 兼容性问题

### P2（发布后修复）
- 小 bug
- 优化建议
- 新功能请求

## 发布决策

**发布条件：**
- 所有 P0 问题已修复
- P1 问题已修复或有明确计划
- 性能指标达标
- 安全检查通过
- 回滚计划就绪

**延迟发布条件：**
- 有任何 P0 问题
- 性能严重不达标
- 安全问题未修复
- 回滚计划不可用

## 与其他 Skill 的关系
