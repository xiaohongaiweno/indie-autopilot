# AI 辅助开发工作流

用 AI 工具提升独立开发者的开发效率。核心问题：如何让 AI 写出高质量代码？如何避免 AI 引入的 bug？如何保持代码质量？

## 铁律

1. **AI 是工具，不是替代。** 你仍然是决策者，AI 只是执行者。
2. **验证所有 AI 生成的代码。** 不要盲目接受，理解每一行代码。
3. **小步迭代。** 一次只让 AI 做一小部分，不要生成大段代码。
4. **保持代码质量。** AI 生成的代码也要符合项目规范。
5. **记录 AI 的局限。** 知道 AI 不擅长什么，避免在这些地方依赖它。

## AI 工具选择

### Cursor
- **适用场景**：全项目上下文、多文件编辑、重构
- **优势**：理解整个代码库、支持长对话
- **最佳实践**：
  - 用 `@file` 引用相关文件
  - 用 `@codebase` 搜索相关代码
  - 用 Composer 做多文件编辑
  - 用 Chat 做代码解释和调试

### GitHub Copilot
- **适用场景**：行内补全、函数生成、测试编写
- **优势**：无缝集成、快速补全
- **最佳实践**：
  - 写清晰的注释和函数签名
  - 接受前阅读建议
  - 用 Copilot Chat 做代码解释

### Claude / ChatGPT
- **适用场景**：复杂问题、架构设计、代码审查
- **优势**：深度推理、长上下文
- **最佳实践**：
  - 提供完整的上下文
  - 要求解释推理过程
  - 要求列出替代方案

## 提示词工程

### 代码生成提示词结构
```
上下文：[项目背景、技术栈、相关文件]
任务：[具体要做什么]
约束：[代码规范、性能要求、兼容性]
输出：[期望的代码格式]
```

### 有效提示词原则
- **具体**：说"用 React 写一个带验证的登录表单"而非"写一个表单"
- **分步**：复杂任务拆成多步
- **示例**：给出期望的输入输出示例
- **约束**：明确不要什么（"不要用 class 组件"）
- **验证**：要求生成测试

### 常见提示词模式

#### 功能实现
```
在 [文件] 中实现 [功能]。
要求：
- 使用 [技术/模式]
- 处理 [边界情况]
- 符合 [代码规范]
- 包含单元测试
```

#### Bug 修复
```
[文件] 中的 [函数] 有 bug。
现象：[描述问题]
期望：[描述正确行为]
请：
1. 分析原因
2. 修复 bug
3. 添加测试防止回归
```

#### 代码审查
```
审查 [文件/函数]。
关注：
- 潜在 bug
- 性能问题
- 安全风险
- 代码可读性
给出具体改进建议。
```

## 工作流模式

### 测试驱动开发（TDD）
1. 让 AI 根据需求写测试
2. 审查测试是否覆盖所有场景
3. 让 AI 写实现代码
4. 运行测试，迭代修复

### 重构模式
1. 让 AI 分析代码问题
2. 让 AI 提出重构方案
3. 逐步应用重构，每步运行测试
4. 让 AI 审查重构结果

### 文档生成
1. 让 AI 根据代码生成文档
2. 补充业务上下文
3. 添加使用示例
4. 审查准确性

## 质量控制

### AI 代码审查清单
- [ ] 代码符合项目规范？
- [ ] 有潜在 bug 或边界情况？
- [ ] 性能是否可接受？
- [ ] 有安全风险？
- [ ] 有测试覆盖？
- [ ] 代码可读性好？
- [ ] 有不必要的复杂性？

### 常见 AI 错误
- **幻觉 API**：编造不存在的 API 或库
- **过时模式**：使用已废弃的语法
- **忽略上下文**：不遵循项目约定
- **过度工程**：添加不需要的抽象
- **安全漏洞**：SQL 注入、XSS 等

### 缓解策略
- 始终运行测试
- 使用 linter 和类型检查
- 手动审查关键逻辑
- 定期更新 AI 工具

## 效率提升技巧

### 快捷键和工作流
- **Cursor**：Cmd+K 快速编辑、Cmd+L 聊天、Cmd+I Composer
- **Copilot**：Tab 接受、Esc 拒绝、Cmd+] 下一个建议
- **通用**：建立常用提示词库

### 上下文管理
- 保持代码库整洁（AI 更容易理解）
- 用清晰的命名和注释
- 维护好的 README 和文档
- 定期清理无用代码

### 批量操作
- 用 AI 做批量重命名
- 用 AI 做批量格式化
- 用 AI 做批量迁移

## 与其他 Skill 的关系

- `indie-tech-architecture`：技术栈指导工具选择
- `security-privacy-review`：安全审查
- `technical-debt-manager`：管理 AI 引入的技术债
- `launch-readiness-qa`：质量检查

## 输出格式

AI 辅助开发不产生独立文档，而是融入开发流程。关键产出：
- 高质量的代码
- 完整的测试覆盖
- 清晰的文档
- 可维护的实现
