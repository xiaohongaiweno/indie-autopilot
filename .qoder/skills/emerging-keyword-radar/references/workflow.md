# 工作流程详解

## 第一步：发现新词

### 输入
- 用户关注的领域/赛道（来自 profile 或对话上下文）
- 上次扫描报告（避免重复）

### 流程
1. 从 `references/sources.md` 选择 2-3 个来源
2. 每个来源扫描 15-30 分钟
3. 记录每个候选词：
   - 关键词原文
   - 来源和发现日期
   - 一句话说明"谁在搜什么、为什么现在出现"
   - 初步分类（五类中的哪一类）
4. 汇总为 10-20 个候选词

### 输出
候选词清单（不评分，只记录）

### 注意
- 不要在发现阶段就评判价值，先广泛收集
- 同一需求的不同措辞算一个候选词，选最常见的表达
- 标注来源，方便后续验证

## 第二步：验证需求

### 输入
- 候选词清单

### 流程
对每个候选词：

1. **搜索验证**：在 Google 搜索该词，观察
   - 前 10 结果是什么类型的页面？
   - 结果质量如何？是否解决了用户问题？
   - 是否有专门的工具页面？

2. **相关词验证**：查看
   - Autocomplete 建议
   - People Also Ask
   - Related Searches
   - 这些相关词是否指向同一个需求？

3. **趋势验证**：在 Google Trends 查看
   - 过去 3 个月趋势
   - 过去 12 个月趋势
   - 是持续上升还是短期脉冲？

4. **搜索量验证**：
   - 有工具就查实际数据
   - 没有就标注"未核实"
   - 用 Autocomplete 存在性作为间接证据

5. **淘汰判断**：
   - 纯新闻热点（无持续需求）→ 淘汰
   - 搜索结果已经有完美答案 → 淘汰或降级
   - 无商业价值的八卦词 → 淘汰

### 输出
通过验证的候选词（5-10 个），附验证证据

## 第三步：判断竞争

### 输入
- 通过验证的候选词

### 流程
对每个候选词：

1. **现有页面分析**：
   - 前 3 结果的内容深度（字数、覆盖范围）
   - 用户体验（页面速度、移动端、设计）
   - 更新频率（最后更新时间）
   - 作者权威性

2. **竞争对手识别**：
   - 是谁在排名？（大站/小站/个人博客）
   - 他们的 DA/DR 是多少？（如有工具）
   - 是否有专门的工具页面？

3. **内容缺口分析**：
   - 现有页面缺少什么？
   - 用户评论/讨论中还在找什么？
   - 是否有新的角度或更好的方式？

4. **排名可行性判断**：
   - 以独立开发者的资源，能否做出更好的页面？
   - 需要多少时间和工作量？
   - 是否有技术壁垒？

### 输出
竞争分析结果，标注每个词的排名可行性（高/中/低）

## 第四步：分类机会

### 输入
- 竞争分析结果

### 流程
对每个候选词：

1. **七维评分**：按 `references/evaluation-framework.md` 打分
2. **执行方向分类**：
   - **写文章**：信息类查询、教程需求 → 博客/指南/教程
   - **做 SEO 页面**：工具类查询、比较需求 → 落地页/对比页/工具页
   - **开发在线工具**：明确任务需求、现有工具不足 → 免费工具/MVP
   - **研究新产品**：产品机会词、持续上升需求 → 验证实验/原型
3. **优先级排序**：按总分排序，≥70 立即执行

### 输出
评分后的候选词列表，含执行方向和具体动作

## 第五步：持续追踪

### 输入
- 本期发现 + 上期追踪记录

### 流程
1. **新增**：本期新发现的候选词加入追踪
2. **更新**：已追踪的词重新评分，记录变化
3. **升级**：观察池中评分上升到 ≥70 的词，进入立即执行
4. **淘汰**：连续 3 次评分下降或无新证据的词，归档
5. **效果追踪**：已执行的词，记录实际效果
   - 内容页：是否发布？排名如何？流量多少？
   - 工具页：是否上线？使用量？转化？

### 输出
更新后的追踪记录，写入 `assets/keyword-tracker.md`

## 运行模式

### 完整扫描（默认）
完整跑 5 步，输出周报。适合"帮我找新关键词机会"。

### 快速扫描
只做第一步和第二步，输出候选词清单。适合"先看看最近有什么新词"。

### 单方向深挖
对指定领域或关键词做第三步和第四步。适合"分析这个词值不值得做"。

### 追踪更新
只做第五步，更新已有记录。适合"更新我的关键词追踪"。
