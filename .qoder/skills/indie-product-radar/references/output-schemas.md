# 输出格式

交付物是一份 Markdown 报告（B 节）。A 节的 JSON 仅供 `scripts/score.py` 内部打分与校验使用，不作为交付物输出给用户。

## A. 内部打分数据（scoreboard.json，非交付物）
顶层是数组，每个元素：

```json
{
  "id": "2026-10-w2-01",
  "name": "机会名称",
  "pos": "为【谁】解决【什么问题】，替代【现有方案】",
  "ind": "行业/场景",
  "s": {"demand":0,"trend":0,"pay":0,"gap":0,"acq":0,"dev":0,"moat":0,"fit":0},
  "sig": ["用户痛点","竞争格局"],
  "veto": [],
  "status": "inbox",
  "fact": "推测",
  "market": "~X 潜在用户 × $Y/年 ≈ $Zk SAM（量级）",
  "pricing": "[模式] $X/月 — [理由]",
  "timing": "太早 / 正好 / 太晚 / 窗口期 — [理由]",
  "acquisition": "前 100 个用户：[渠道 1 + 动作]、[渠道 2 + 动作]；获客成本粗估：$X/用户",
  "wedge": "切入楔子：MVP 的单一核心功能",
  "exp": "7 天验证实验与成功判据",
  "notes": "【事实】…\n【推测】…\n【风险】…\n【创始人匹配】…",
  "links": "https://…\nhttps://…",
  "ts": 1760000000000,
  "validation_result": "验证实验实际结果（可选，验证后填写）",
  "calibration_note": "校准反思（可选，验证后填写）",
  "last_validated": 1760000000000
}
```

枚举值（必须逐字一致，脚本依赖它们；此格式也与"产品雷达看板"兼容）：
- `s.*`：整数 0–10（八维：demand, trend, pay, gap, acq, dev, moat, fit）
- `sig` 取自：`SEO/需求` `热点/趋势` `新兴产品` `用户痛点` `商业化` `竞争格局`
- `veto` 取自：`依赖单一平台 API 且无替代` `重度合规` `需冷启动双边网络` `消费级低付费且无广告模式`
- `status`：`inbox` `watch` `validating` `building` `archived`
- `fact`：`事实` `部分验证` `推测`
- `market`：字符串，市场规模粗估（如 "~5000 潜在用户 × $29/月 ≈ $1.7M SAM"）；找不到数据写"未估算"
- `pricing`：字符串，定价建议（如 "订阅制 $29/月 — 竞品均价 $49，我们更便宜且功能更专注"）
- `timing`：字符串，时机风险评估（如 "正好 — 需求明确，竞品有弱点"）
- `acquisition`：字符串，获客路径具体化（如 "前 100 个用户：Reddit r/selfhosted 发帖、HN Show HN、Twitter #buildinpublic；获客成本粗估：$5/用户"）
- `links`：换行分隔；`fact` 为 `事实`/`部分验证` 时至少 1 条
- `ts`：毫秒时间戳；`id` 唯一，更新已有机会时沿用原 id
- `validation_result`：可选，验证实验实际结果
- `calibration_note`：可选，校准反思
- `last_validated`：可选，最后验证时间戳（毫秒）

`sig` 只能勾选**有真实来源支撑**的类型。

## B. 机会卡（报告中使用的交付格式）
```
【机会名称】
一句话定位：为 [谁] 解决 [什么问题]，替代 [现有方案]
总分：xx / 100   状态：验证中 / 观察 / 归档   证据强度：事实 / 部分验证 / 推测
市场规模：~X 潜在用户 × $Y/年 ≈ $Zk SAM（量级）
定价建议：[模式] $X/月 — [理由]
时机：太早 / 正好 / 太晚 / 窗口期 — [理由]
创始人匹配度：X/10 — [一句话说明为什么是你做这个]

信号证据（至少 3 类）
- 需求：关键词、搜索量（或"未核实"）、趋势
- 痛点：[链接] 用户原话摘要
- 竞品：A（定价，更新状态，弱点）、B …
- 商业化：公开收入 / 定价区间 / 广告 / 出售记录

竞争空隙：1–2 点
切入楔子：单一核心功能
获客路径：
- 前 100 个用户：[渠道 1 + 动作]、[渠道 2 + 动作]、[渠道 3 + 动作]
- 获客成本粗估：$X/用户（或 X 小时/用户）
- 分发渠道：已有 / 需要 X 个月建设
风险与否决项：
7 天验证实验：动作 + 成功判据
验证失败后路径：痛点不成立→放弃 / 付费不足→调定价 / 获客难→调渠道
不确定点（需人工确认）：
```

## C. 机会对比矩阵（报告中使用的交付格式）

用于 Top 3 机会的横向对比，帮助决策"先做哪个"。

```
| 机会 | 总分 | 可行性（dev+acq+fit 均值）| 回报潜力（demand+pay 均值）| 市场规模 | 时机 | 建议优先级 |
|---|---|---|---|---|---|---|
| A | 78 | 7.3 | 8.0 | $1.7M SAM | 正好 | ★ 先做 |
| B | 72 | 6.5 | 7.5 | $800k SAM | 窗口期 | 观察 |
| C | 68 | 8.0 | 6.0 | $500k SAM | 太晚 | 备选 |
```

**决策指引**：
- 可行性高 + 回报潜力高 → 立即做
- 可行性高 + 回报潜力低 → 作为副项目或模板产品
- 可行性低 + 回报潜力高 → 需要找合伙人或调整方向
- 可行性低 + 回报潜力低 → 不做
