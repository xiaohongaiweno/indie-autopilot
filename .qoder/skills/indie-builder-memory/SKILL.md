# 独立开发者经验沉淀

跨项目沉淀经验和学习。核心问题：学到了什么？如何避免重复犯错？如何复用成功经验？

## 铁律

1. **记录学习。** 不记录的学习会遗忘。
2. **具体 > 泛泛。** 具体的例子和场景，不是抽象的原则。
3. **可操作。** 经验要能指导未来的决策。
4. **定期回顾。** 经验需要定期回顾和更新。
5. **分享学习。** 分享学习帮助自己和他人。

## 经验类型

### 产品经验
- **需求验证**：什么方法有效？什么方法无效？
- **用户研究**：如何理解用户？常见误区？
- **定价策略**：什么定价有效？什么定价失败？
- **发布策略**：什么渠道有效？什么时机最好？

### 技术经验
- **技术选型**：什么技术栈适合独立开发者？
- **架构决策**：什么架构模式有效？
- **性能优化**：什么优化方法最有效？
- **安全实践**：常见的安全陷阱？

### 商业经验
- **获客策略**：什么渠道 ROI 高？
- **转化优化**：什么方法提升转化？
- **用户留存**：什么方法提升留存？
- **定价优化**：如何优化定价？

### 流程经验
- **开发流程**：如何提升开发效率？
- **时间管理**：如何管理独立开发时间？
- **优先级排序**：如何决定做什么？
- **工具使用**：什么工具最有效？

## 经验记录格式

### 经验卡片
```
# 经验标题

## 背景
- 项目：...
- 时间：...
- 场景：...

## 经验
- 发生了什么？
- 学到了什么？

## 应用
- 何时应用这个经验？
- 如何应用？

## 证据
- 支持这个经验的证据
- 相关链接

## 标签
- #产品 #验证 #定价 ...
```

### 决策记录
```
# 决策标题

## 背景
- 面临什么问题？
- 有哪些选择？

## 决策
- 选择了什么？
- 为什么选择这个？

## 结果
- 结果如何？
- 学到了什么？

## 教训
- 下次会怎么做？
```

## 工作流程

### 1. 捕获经验
- 项目结束时回顾
- 遇到重要问题时记录
- 学到新东西时记录
- 犯错时记录

### 2. 整理经验
- 分类（产品/技术/商业/流程）
- 标签（相关主题）
- 提取关键学习
- 关联相关经验

### 3. 验证经验
- 在其他项目中验证
- 收集更多证据
- 更新或修正经验
- 标记置信度

### 4. 应用经验
- 新项目时查阅
- 做决策时参考
- 遇到问题时搜索
- 分享给他人

### 5. 更新经验
- 定期回顾
- 根据新证据更新
- 删除过时的经验
- 合并相似经验

## 经验检索

### 检索方式
- **关键词搜索**：搜索关键词
- **标签过滤**：按标签过滤
- **主题浏览**：按主题浏览
- **相关经验**：查看相关经验

### 检索场景
- 开始新项目：查阅类似项目的经验
- 做技术决策：查阅技术选型经验
- 遇到问题：搜索解决方案经验
- 定期回顾：浏览最新经验

## 经验质量

### 高质量经验
- **具体**：有具体的例子和场景
- **可验证**：有证据支持
- **可操作**：能指导未来决策
- **时效性**：经验仍然适用

### 低质量经验
- **泛泛**：没有具体例子
- **未验证**：只是个人感受
- **不可操作**：无法指导决策
- **过时**：不再适用
