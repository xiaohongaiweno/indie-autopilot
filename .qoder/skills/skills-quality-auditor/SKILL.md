# Skills 质量审计

审计 Skill 家族的质量和有效性。核心问题：Skills 符合规范吗？有重复工作吗？覆盖完整吗？有效吗？

## 铁律

1. **结果 > 数量。** 以实际效果衡量，不是 Skill 数量。
2. **不重复。** 每个 Skill 做独特的事，不重复工作。
3. **可验证。** 质量可以验证，不是主观感受。
4. **持续改进。** 定期审计，持续改进。
5. **用户优先。** Skill 为用户服务，不是为完整而完整。

## 审计维度

### 1. 规范合规性
- **SKILL.md 存在**：每个 Skill 都有 SKILL.md
- **前置元数据**：name 和 description 正确
- **描述质量**：描述清晰、完整、触发词明确
- **行数限制**：SKILL.md < 500 行
- **无多余文件**：没有 README.md、CHANGELOG.md 等

### 2. 内容质量
- **铁律明确**：有明确的铁律和约束
- **工作流程清晰**：有清晰的工作流程
- **输出格式明确**：有明确的输出格式
- **与其他 Skill 关系**：明确与其他 Skill 的关系
- **参考资源**：有必要的参考资源和模板

### 3. 覆盖完整性
- **生命周期覆盖**：覆盖完整的产品生命周期
- **无覆盖缺口**：没有重要的领域未覆盖
- **无重复覆盖**：没有多个 Skill 覆盖同一领域

### 4. 交接清晰度
- **交接关系明确**：Skill 间的交接关系清晰
- **交接点明确**：明确的交接点和触发条件
- **无交接缺口**：没有交接缺口

### 5. 实际效果
- **使用频率**：Skill 被使用的频率
- **用户满意度**：用户对 Skill 的满意度
- **结果质量**：Skill 产出的质量
- **效率提升**：Skill 提升的效率

## 审计流程

### 1. 准备
- 列出所有 Skills
- 收集使用数据
- 收集用户反馈
- 准备审计清单

### 2. 规范审计
对每个 Skill：
- 检查 SKILL.md 存在
- 检查前置元数据
- 检查描述质量
- 检查行数
- 检查多余文件

### 3. 内容审计
对每个 Skill：
- 评估铁律质量
- 评估工作流程
- 评估输出格式
- 评估参考资源

### 4. 覆盖审计
- 检查生命周期覆盖
- 识别覆盖缺口
- 识别重复覆盖

### 5. 交接审计
- 检查交接关系
- 检查交接点
- 识别交接缺口

### 6. 效果审计
- 分析使用数据
- 分析用户反馈
- 评估结果质量
- 评估效率提升

### 7. 改进建议
- 优先级排序
- 制定改进计划
- 分配责任
- 设定时间线

## 常见问题

### 规范问题
- **描述不完整**：缺少触发词或场景
- **行数过多**：需要拆分到 references/
- **多余文件**：需要删除 README.md 等

### 内容问题
- **铁律不明确**：需要明确约束
- **工作流程不清晰**：需要细化步骤
- **输出格式不明确**：需要明确格式

### 覆盖问题
- **覆盖缺口**：需要新增 Skill
- **重复覆盖**：需要合并或重新划分

### 交接问题
- **交接关系不明确**：需要明确关系
- **交接点不明确**：需要明确触发条件

## 审计频率

- **月度**：快速检查规范合规性
- **季度**：深度审计内容和效果
- **年度**：全面审计覆盖和交接

## 与其他 Skill 的关系

- 所有 Skills：审计所有 Skills 的质量
- `indie-builder-memory`：沉淀审计经验
