# 技术债务管理

管理系统性的技术债务。核心问题：有什么技术债务？影响多大？何时偿还？

## 铁律

1. **有意为之的债务是工具。** MVP 阶段的技术妥协是有意的，不是无知的。
2. **记录所有债务。** 不记录的债务会变成永远的债务。
3. **定期偿还。** 每个版本留 20% 时间还债。
4. **优先级排序。** 不是所有债务都要还，优先还影响大的。
5. **防止新债。** 建立规范，防止新的技术债务。

## 技术债务类型

### 代码债务
- **重复代码**：相同逻辑多处实现
- **过长函数**：函数超过 50 行
- **复杂逻辑**：难以理解的嵌套
- **魔法数字**：硬编码的数字
- **缺少注释**：关键逻辑没有解释

### 架构债务
- **紧耦合**：组件高度依赖
- **缺少抽象**：没有合适的接口
- **单体过大**：单体应用过于庞大
- **缺少测试**：关键路径没有测试
- **不一致的模式**：不同地方用不同模式

### 基础设施债务
- **手动部署**：没有自动化部署
- **缺少监控**：没有监控和告警
- **硬编码配置**：配置写死在代码里
- **缺少文档**：基础设施没有文档
- **过时的依赖**：依赖版本过旧

### 文档债务
- **过时的文档**：文档和代码不一致
- **缺少的文档**：关键功能没有文档
- **不清晰的文档**：文档难以理解
- **缺少的 README**：项目没有 README

## 债务评估

### 影响评估
- **高影响**：阻碍新功能开发、频繁导致 bug、影响性能
- **中影响**：降低开发速度、增加理解成本
- **低影响**：代码不美观、小的不一致

### 紧急程度
- **紧急**：正在导致问题，需要立即处理
- **重要**：即将导致问题，本版本处理
- **计划**：未来会导致问题，下个版本处理
- **观察**：可能成为问题，持续监控

### 偿还成本
- **低**：< 1 天
- **中**：1-3 天
- **高**：1-2 周
- **很高**：> 2 周

## 工作流程

### 1. 识别债务
- 代码审查发现
- 开发过程中遇到
- Bug 修复时发现
- 性能问题追溯
- 定期代码审计

### 2. 记录债务
对每个债务：
- **描述**：什么是技术债务？
- **位置**：在哪个文件/模块？
- **原因**：为什么产生？
- **影响**：有什么影响？
- **解决方案**：如何偿还？
- **成本估算**：需要多少时间？
- **优先级**：P0/P1/P2/P3

### 3. 优先级排序
- 影响 × 紧急程度
- 考虑偿还成本
- 考虑战略价值
- 排序并选择

### 4. 计划偿还
- 每个版本留 20% 时间
- 选择高优先级的债务
- 分解为可执行的任务
- 纳入版本计划

### 5. 偿还债务
- 重构代码
- 添加测试
- 更新文档
- 优化架构

### 6. 验证和记录
- 验证债务已偿还
- 更新文档
- 记录学习
- 更新债务清单

## 债务预防

### 代码规范
- **Linting**：ESLint、Prettier
- **代码审查**：每次 PR 都要审查
- **测试覆盖**：关键路径必须有测试
- **文档要求**：关键功能必须有文档

### 架构规范
- **设计审查**：重大变更要审查
- **架构决策记录**：记录重要决策（ADR）
- **依赖管理**：定期更新依赖
- **性能预算**：设定性能指标

### 流程规范
- **定义完成**：明确"完成"的定义
- **技术债务预算**：每个版本留时间还债
- **定期审计**：每月审查技术债务
- **持续改进**：不断优化流程

## 债务追踪

### 追踪工具
- **Issue Tracker**：GitHub Issues、Linear
- **专门标签**：`tech-debt` 标签
- **专门看板**：技术债务看板
- **文档**：TECH_DEBT.md 文件

### 追踪指标
- **债务数量**：总债务数量
- **债务趋势**：新增 vs 偿还
- **偿还速度**：每月偿还多少
- **债务年龄**：债务存在多久

## 常见技术债务场景

### MVP 阶段的有意债务
- 硬编码配置
- 同步处理
- 基础错误处理
- 手动部署
- 缺少测试

**何时偿还**：产品验证成功后

### 快速增长期的债务
- 快速添加的功能
- 临时的解决方案
- 跳过的代码审查
- 延迟的文档

**何时偿还**：增长稳定后

### 长期积累的债务
- 过时的依赖
- 不一致的模式
- 缺少的抽象
- 复杂的代码

**何时偿还**：持续改进
